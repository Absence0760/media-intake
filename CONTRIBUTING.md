# Contributing

Thanks for helping. media-intake handles people's private photos, so the bar
is: nothing leaves the machine, nothing is deleted without an explicit yes,
and every change comes with tests.

## Git workflow

- Every change reaches `main` through a pull request; `main` is protected and
  its required check is `CI gate` (`.github/workflows/ci.yml`). PRs are
  squash-merged.
- Branch from `origin/main` in a worktree:
  `git fetch origin && git worktree add ../media-intake-<slug> -b <type>/<slug> origin/main`.
- PR titles are conventional commits: `<type>(<scope>): <subject>`, type one
  of feat, fix, chore, docs, refactor, test, perf, ci, build, revert; subject
  lowercase, no trailing period (`pr-title-lint` checks it).
- After the first push, update a branch by merging `origin/main`; never rebase
  and force-push a shared branch.
- Never `git stash` (one stack shared by every worktree); park work as a patch.
- `pre-commit install` once: gitleaks scans every commit.

## Code

- Python standard library first. The system Python (3.11+) runs the CLI; the
  venv from `setup.sh` runs only the ML pieces (NudeNet, SigLIP, scipy).
- Every download and dependency is pinned and at least 7 days old; see Pins.
- No network calls at run time except to `127.0.0.1` (Ollama). No telemetry.
- Originals are never written: tags go in XMP sidecars.
- An assistant or tool must never read, view or describe a quarantined or
  flagged file; keep output to counts and paths.

## Pins

Pins are regenerated by a script, never hand-edited:

- `requirements.txt` and `requirements-labels.txt`: hash-pinned wheels (Linux
  x86_64 and pure, for the system Python), installed by `setup.sh` with
  `--require-hashes --no-deps`.
- `requirements-browser.txt`: Playwright and its dependencies for the
  real-browser tests (Tests, below), never the app. Resolved for CPython 3.12
  (CI, Ubuntu 24.04) and 3.14 (Fedora 43), with no system packages; both
  resolutions must agree, and each pin lists the fitting wheels of both.
- `media_intake/pins.json`: the SigLIP revision and each model file's sha256,
  and the Ollama model's digest. `setup.sh`, the tools and `media-intake
  doctor` all read this file; no pin is written anywhere else
  (`tests/test_cli.py` checks).

`scripts/update-pins.py` writes these four files and nothing else. To bump
them, on Fedora with [uv](https://docs.astral.sh/uv/) >= 0.9.17:

```sh
python3 -I scripts/update-pins.py --check   # what would change; exit 1 if anything
python3 -I scripts/update-pins.py           # rewrite the files
bash setup.sh && media-intake doctor        # fetch and verify what moved
```

When `requirements-browser.txt` moved, also reinstall `.venv-browser` and run
the browser tests (Tests, below).

Nothing newer than 7 days is taken: wheels go through `uv pip compile
--exclude-newer <cutoff>`, SigLIP moves to the newest commit older than the
cutoff (only if a pinned file changed, and never back to a commit older than
the pinned one), and a new Ollama digest is first
recorded as `ollama.candidate` and pinned only by a run 7 or more days later
(the registry publishes no dates). `--cutoff` takes an earlier RFC 3339 time.
System packages `setup.sh`'s venv reuses (numpy, packaging) are resolved
against the installed versions and never pinned (`requirements-browser.txt`
has none); deliberate holds (`HOLDS`) and each
file's inputs live at the top of the script. The script reads metadata from
PyPI, Hugging Face and the Ollama registry and never downloads model weights;
the tests run it against fakes.

A SigLIP move also needs `bash setup.sh --build-labels` (labels.npz) and a
check of `label.py`'s logit scale, bias and preprocessing; an Ollama move
needs `ollama pull` and makes `vlm-trash` judge files again. Put the
script's output in the PR body. A pin bump is its own PR, model-tested
(below) before a release; cutting one: [docs/release.md](docs/release.md).

**The script is the source of truth, Dependabot only a prompt.** Its `pip`
entry (`.github/dependabot.yml`) covers the repo root, so it can open a PR
bumping any of the three requirements files, but Dependabot neither knows this repo's per-file wheel
set (the system Python, or 3.12 + 3.14) nor the holds, and its 7-day
cooldown counts from the release, not from each file's upload. Never merge
such a PR as Dependabot wrote it: on its branch, run `python3 -I
scripts/update-pins.py --only requirements` and commit what the script
writes. If the script doesn't produce the bump (not 7 days old yet, or held),
close the PR.

## Tests

- Every change updates its tests and docs in the same PR.
- Tests use synthetic media only (Pillow drawings, ffmpeg test patterns) in a
  throwaway HOME. Never commit a real photo, path, device id or batch name.
- Run what you touched: `python3 -I -m unittest discover -s tests -p "test_<area>.py"`; the full
  suite is `python3 -I -m unittest discover -s tests`. Tests that need the
  venv, the models or Ollama skip themselves when those are missing.
- `tests/test_offline_guard.py` enforces "nothing leaves the machine" from the
  source: network clients only in `vlm_trash.py`, HTTP servers bound to
  `127.0.0.1`, no runtime downloaders. A new legitimate use changes its
  allow-list in the same PR, so it gets reviewed.
- Those model tests skip in `ci.yml` (no venv or models there).
  `.github/workflows/models.yml` runs them nightly and on demand ("Run
  workflow" in the Actions tab) in a Fedora 43 container, after `setup.sh`,
  and fails if any test skips except the real-Ollama one (`VLM_REAL`, which
  needs a GPU; run it locally). It is not a required check and doesn't run on
  pull requests: run it on your branch to model-test a pin bump, and on
  `main` before a release.
- When a test fails, fix the test if it is wrong, or the code if it is; never
  loosen an assertion or add a sleep to make it pass.
- Real-browser tests (`tests/browser/`, Playwright + headless Chromium) drive
  the gallery and the review page: keys, selection and the bottom selection
  bar, the confirm dialogs (ERASE typed), lightbox video autoplay and Space
  play / pause, Range seeking, and the detached job's
  progress, including re-attaching after a reload. They skip with a reason
  when Playwright or its Chromium is missing, so the commands above are
  unaffected; the `browser` job in `ci.yml` runs them (and fails, not skips,
  through `MEDIA_INTAKE_BROWSER_REQUIRED=1`). Locally, once:

  ```sh
  python3 -m venv --system-site-packages .venv-browser   # gitignored; reuses the system Pillow
  .venv-browser/bin/pip install --require-hashes --no-deps -r requirements-browser.txt
  PLAYWRIGHT_BROWSERS_PATH=$PWD/.venv-browser/browsers .venv-browser/bin/python -m playwright install --only-shell chromium
  ```

  Then run them (one file with `-p test_browser_gallery.py`):

  ```sh
  PLAYWRIGHT_BROWSERS_PATH=$PWD/.venv-browser/browsers .venv-browser/bin/python -I -m unittest discover -s tests/browser -t tests
  ```

  The browser comes only from that explicit install, never at import; it is
  the build the pinned Playwright names. The video tests make a 30 s H.264
  test pattern with ffmpeg (`libx264` or `libopenh264`) and skip without one.
  Tests wait on real signals (`data-ready`, `data-job`, media events), never a
  sleep; the hooks each file relies on are listed in its docstring.
  `requirements-browser.txt` is bumped with the other pins by
  `scripts/update-pins.py` (Pins, above; 7 days old, hashes for CPython 3.12
  and 3.14); after a bump, reinstall the venv with the `pip install` line
  above and run these tests.
